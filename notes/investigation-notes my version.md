## 1. Investigation Objective

Investigate how Linux DNS resolver configuration is managed and determine whether file-level monitoring can capture unexpected changes.

The investigation focused on:

- Identifying the active DNS management component.
- Recording the existing resolver configuration.
- Establishing a file-integrity baseline.
- Adding targeted Auditd watches.
- Performing a controlled file modification.
- Reviewing the resulting Auditd records.
- Validating DNS resolution.
- Removing lab-specific monitoring rules and test data.

## 6. Controlled Modification Test

A separate test directory was created:

```bash
sudo mkdir -p /var/tmp/lab136
```

The test file was created with:

```text

search lab136.invalid
```

The address `192.0.2.53` is in the TEST-NET-1 documentation range. It was used only as sample data in a separate test file.

A dedicated Auditd watch was added:

```bash
sudo auditctl -w /var/tmp/lab136/ -p wa -k lab136_dns_test
```

## 11. Final Assessment

### Confirmed

- NetworkManager was active.
- `/etc/resolv.conf` was a regular file generated by NetworkManager.
- The configured DNS server was `192.168.203.2`.
- `nmcli` reported the same DNS server for `ens160`.
- systemd-resolved was not installed.
- Auditd was active and initially reported `lost 0`.
- Resolver-related and test-directory Auditd watches were installed.
- A controlled test-file modification was captured by Auditd.
- The test file's SHA-256 changed after modification.
- DNS resolution succeeded through `192.168.203.2`.
- Lab-specific Auditd rules were removed.
- The test directory was deleted.

### Not Established

- Unauthorized modification of `/etc/resolv.conf`.
- Unauthorized modification of NetworkManager configuration.
- DNS server replacement or malicious DNS redirection.
- DNS poisoning.
- Malicious DNS traffic or command-and-control activity.
- Wazuh dashboard alert ingestion for the controlled test.
